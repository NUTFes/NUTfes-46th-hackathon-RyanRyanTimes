# 良良タイムズ 要件定義（作成中）

## 目的
頑張っている局員にスポットライトを当て、うれしい気持ちになってもらう。あわせて、本人が自分では気付いていない良さに気付いてもらう。

## 背景・課題
- 貢献が見えない：レビュー・質問への回答・リアクションでの応援など、目立たない貢献は本人も周りも気付きにくい
- 他の人が何をしているか知らない：チームや学年をまたぐと、誰がどんな活躍をしているかが伝わらない

## コンセプト
**良良記者が毎月、情報局の「いい話」を取材して届ける局内新聞。**
- 競争より称賛。順位を競う場ではなく、活躍を見つけて記事にする場
- 全員の記事を必ず作るわけではない。その月に光る活躍があった人を記事にする
- 「頑張った」と言えることは何でも記事の種にする（たくさんやった／支えた・応援した／伸びた・初挑戦／喜ばれた・続けた、ほか）
- 記事の種は2つ：データ（GitHub・Slack の活動）と、仲間からのタレコミ
- 良さは紙面で伝える。紙面だけで足りなければ、あとで本人だけが見る個人欄を足す
- 月刊（毎月はじめに前月号）＋年度末の年間特大号

## ユーザーと権限
| ユーザー | 説明 | ログイン |
|---|---|---|
| 読者 | 紙面を読む人。局外の人も含む | 不要 |
| 局員 | 情報局（NUTMEG）のメンバー。タレコミを送る、自分の記事を取り下げる、オプトアウトする | Slack ログイン |
| 編集部 | 局員のうち数人。下書きを直し、載せる記事を決めて号を発行する | Slack ログイン＋編集部に登録済み |
| 良良（システム） | 活動を集計し、記事の下書きを書く記者 | - |

## 要求
1. 局員は、Slack でログインして、誰かの頑張りをタレコミできる。対象者と、何が良かったかを書く
2. タレコミは記名か匿名かを送り主が選べる。匿名の場合、送り主の名前は紙面にも対象者にも出さない（編集部は分かる）
3. GitHub（nutfes org）と Slack（NUTMEG）の活動を月ごとに集計し、記事の種になりそうな頑張り（量・支え・伸び・初挑戦・反応・継続）を見つける
4. 良良は、集計結果とタレコミから記事の下書きを書く。下書きには根拠（数字、元の投稿、タレコミ本文）を添える
5. 編集部は、下書きを直し、載せる・載せないを決め、号を組んで発行する。編集部の確認を経ない記事は公開しない
6. 号は月刊（毎月はじめに前月分）と年間特大号の2種類とする
7. 発行した号は、ログインなしで誰でも読める
8. 記事になった本人は、発行後に自分の記事を取り下げられる。取り下げた記事は紙面から消える
9. 局員は、「記事にしないで」と設定できる（オプトアウト）。オプトアウト中の人は集計・下書き・タレコミの対象にならず、過去の記事を含めて本人のデータを全部消す
10. 記事を画像で保存できる（Slack や SNS に貼るため）
11. 記事は人を傷つけない。比較で下げる表現、ミスや不在への言及はしない
12. 号の発行時に、記事になった本人へ Slack DM で掲載を知らせる
13. 発行後に誤りが見つかったら、編集部が記事を直して公開し直すか、非公開にできる。取り下げ・非公開の記事は存在しない扱いにする
14. Slack の履歴は 90 日で消えるため、毎月取り込んで1年間保存する。1年を過ぎたものは消す

## 状態の流れ
- タレコミ：受付 → 採用（記事に使った）／見送り
- 記事：下書き → 掲載決定 → 公開 → 取り下げ（本人）／非公開（編集部）。掲載しないものは「不掲載」。公開中の訂正は状態を変えずに本文だけ直す
- 号：編集中 → 発行

## 制約・前提
- Web で作る（ハッカソンのレギュレーション）。読者にアプリのインストールやログインを求めない
- 対象は情報局のみ。集計するのは公開チャンネルの投稿だけで、DM・非公開チャンネルは見ない
- PoC では Slack のデータを Claude Code の Slack コネクターで取得する。本番は Bot トークンに置き換える
- 記事の下書きは LLM で書く（API キーが必要）
- 締切：11/17 中間レビュー、11/24 成果発表

## スコープ

- 今回は保留：本人だけの個人欄、Slack Bot での自動送信（全体への発行告知・掲載通知）、他局への展開
